# 工具页 SEO

[PROTOCOL]: 变更时更新此头部，然后检查 AGENTS.md

## 适用范围

用于单个 AI generator、maker、remover、enhancer、converter、editor 或其他工具型 SEO 页面。不要用于普通 landing page、博客、新闻、campaign 页面或 programmatic 批量页。

最接近的 route 或模板不明确时，先停下确认。不要发明新的组件体系。

## 必要输入

- `CORE_KEYWORD`：一个英文主关键词。
- 用户提供的模板 route 或 JSON；未提供时扫描仓库。
- 交付模式：直接编辑、只写 JSON、只写 brief。
- 产品限制：格式、尺寸、时长、价格、登录、安全、隐私、法务约束。

只写英文 source JSON。多语言同步属于后续 i18n 流程。

## 仓库扫描

找到最接近的现有工具页：

- App Router 页面：`app/**/page.tsx` 或 `app/**/page.jsx`
- i18n 来源：`messages/`、`locales/`、`i18n/`、`next-intl`、`next-i18next`
- 共享 wrapper、metadata、schema、breadcrumb、related tools、analytics
- source JSON 结构和 import 路径

保留模板 route shape 和 JSON shape。只改新增页面必需的 slug、namespace、imports、identifiers、related links 和页面文案。

## SERP 工作

按 `serp-research.md` 执行搜索深度与抓取。功能页默认分析 5 个有效结果；关键词竞争强或用户要求深度研究时再分析 10 个。

输出紧凑关键词地图：

- 1 个主关键词
- 3-5 个语义变体
- 3-6 个 FAQ/PAA 问题
- 2-4 个相关工具或内链目标
- 若站内已有页面覆盖同一意图，说明 cannibalization 风险

AI/GEO 补充：当关键词属于 AI 工具、商业比较、best-for、替代品或高意图任务时，额外写 5-10 个 fan-out 查询假设。覆盖替代方案、适合人群、价格/积分、限制、格式、质量、安全、隐私、对比和下一步任务；这些查询用于决定 FAQ、事实层、相关内链和可引用答案块。

## 工具页类型

先判断工具页类型，再决定模块轻重。不要把所有页面套成同一条长模板。

| 类型 | 典型关键词 | 首屏重点 | 必备模块 | 可省或降权 |
|---|---|---|---|---|
| 删除类 | `background remover`、`watermark remover`、`object remover`、`text remover` | 上传入口、处理模式、支持格式、隐私或合法使用提醒 | 能力边界、工作步骤、示例/效果、信任与合规、FAQ、相邻工具 | 模型技术解释；泛泛行业介绍 |
| 批量类 | `batch background remover`、`bulk watermark remover` | 批量容量、单次限制、计费单位、格式限制、回到单图工具的路径 | 工具入口、能力边界、简短步骤、相关工具、FAQ | 大段 Features、重复使用场景、冗长口碑模块 |
| 生成/编辑类 | `AI image generator`、`AI photo editor`、`image maker` | prompt、模式、模型、比例、分辨率、积分或价格、示例 prompt | 模型/模式选择、工作步骤、用例、示例、能力边界、FAQ | 隐藏价格或积分；空泛创意口号 |
| 增强/修复类 | `image upscaler`、`photo restoration`、`unblur image` | before/after、输入质量、输出尺寸、自然度边界、隐私 | 示例/效果、质量边界、使用场景、工作步骤、信任与合规、FAQ | 绝对修复承诺；伪造对比图 |
| 转换类 | `image converter`、`video converter`、`format converter` | 输入输出格式、压缩或质量选项、速度/大小限制 | 格式表、工作步骤、批量能力、FAQ、相关工具 | 与转换无关的创作类卖点 |
| 模型页 | 模型名 + `AI editor`、`AI image generator` | 已选模型、模型差异、价格/积分、可执行入口 | 模型差异、适合任务、限制、示例、与通用工具的关系、FAQ | 泛泛模型新闻；脱离工具入口的介绍 |

## 模块信息价值与 SEO QA

每个模块都必须同时通过三项检查：

- 用户价值：帮助用户理解或完成当前工具任务。
- 信息增量：提供 SERP 竞品没有讲清的示例、限制、场景、步骤、证据、对比或边界。
- 可索引性：内容在可抓取 HTML 中，结构清晰，能被搜索引擎和 AI search 引用。

| 模块 | 必须讲清 | 信息价值要求 | SEO QA |
|---|---|---|---|
| 首屏任务区 | 工具名、核心承诺、真实入口、输入方式、处理模式、关键限制 | 按工具页类型展示用户最先决策的信息；让用户不滚动也知道能做什么、怎么开始、有什么边界 | 首屏可先出现工具面板再出现 SEO H1；关键说明必须可抓取 |
| Hero / H1 | 工具是什么、处理什么输入、输出什么结果、适合谁 | 1-2 句直接回答搜索意图，不写空泛品牌口号 | H1 或同级主标题自然包含主关键词，优先靠前但不强制第一个词；title/H1 同向但不机械重复 |
| 工具入口 | 用户如何开始：上传、输入、选择模式、生成、预览或跳转到真实工具 | 首屏必须让用户看到可执行路径；暂不可用时说明真实状态 | 不做假上传、假进度条、假生成；关键入口可被抓取或有可抓取说明 |
| 能力边界 | 支持格式、尺寸、时长、分辨率、价格、登录、处理模式、平台限制 | 说明用户决策需要的限制，避免过度承诺；限制优先放在工具入口附近 | 只有真实可验证时才写 free、no signup、instant、速度、精度、质量或模型能力 |
| 机器可读事实层 | 支持格式、输出、限制、价格/积分、登录要求、隐私、更新时间、模型/模式、适合任务 | 把用户和 AI search 最需要引用的事实整理成短表格、Key facts 或 Key features；不是重复营销文案 | 关键事实必须在可抓取 HTML 中，优先服务端输出；不要只放在图片、折叠后交互态或客户端异步结果里 |
| 工具类型差异化 | 删除类讲合法使用，批量类讲容量/计费，生成编辑类讲模型/prompt，增强修复类讲自然度和输入质量，转换类讲格式 | 每页至少有一个由工具类型带来的独特判断，而不是换关键词复用同一段 | 相似页面必须能用首屏、模块和内链解释清楚意图区分 |
| 工作步骤 | `input -> configure -> process -> preview/output` | 每一步写用户动作和系统结果，不只写营销动词 | 步骤顺序可读，可映射 HowTo/FAQ 时才加对应 schema |
| Features | 真实能力和对应收益 | 每条只讲一个能力，说明它解决什么具体问题 | 避免同义词堆叠；关键词变体自然出现 |
| 使用场景 | 任务、素材类型、用户场景、发布渠道 | 覆盖 SERP/PAA 中的真实需求，而不是泛泛写 creator/team | 场景之间有差异，不能成为 doorway 关键词堆砌 |
| 示例/效果 | before/after、输出类型、风格、质量边界、截图或真实案例 | 没有真实素材时只描述可验证的结果方向，不伪造评价或数据 | 图片有描述性 alt 和稳定尺寸/比例；可见内容与 schema 一致 |
| 证明/可信信号 | 真实样例、before/after、可验证数据、评价、品牌或安全说明 | 只有产品确有证据时才写数字、评分、用户量、速度、质量或评价；没有证据就用示例和边界说明替代 | 不伪造 testimonials、统计值、合作品牌或性能数据 |
| 答案块/可引用块 | 每个核心 H2 下先用 1-2 句直接回答该小节问题，再展开步骤、限制或例子 | 让用户、featured snippets 和 AI search 能独立摘取清晰答案；H2/H3 避免 `Step 1`、`Feature 1` 这类空标题 | 段落短，语义完整；FAQ 使用真实问题，不为 schema 硬造问答 |
| 来源与透明度 | 谁提供工具或内容、能力依据来自哪里、AI/自动化是否影响页面或结果、页面为什么独立存在 | 对工具页写清产品事实来源；对 AI 生成或辅助内容，在用户合理期待时说明生成或审阅方式 | 不伪装人工测试、作者经验、产品数据或更新时间 |
| 信任与合规 | 隐私、文件处理、版权、身份、敏感编辑、合法使用 | 解释用户风险和平台边界，尤其是 remover/editor 类工具 | 涉及版权/隐私/身份时必须可见；不得隐藏在页脚小字里 |
| FAQ | SERP/PAA 问题、产品顾虑、限制、质量、安全、移动端、格式 | 回答具体、保守、可操作；不知道就写依赖现有产品流程 | FAQ schema 只标记页面可见问答 |
| 相关工具 | 正文放 2-4 个强相关工具；页尾工具墙可放更多相邻或上级分类工具 | 正文链接解释下一步任务关系；页尾工具墙必须同类、相邻或上级分类相关 | 使用真实 `<a href>`；锚文本描述目标页；避免 `Learn more` |

## 测试与 GEO 校准

SearchPilot 类控制实验只能转成测试假设，不能当成跨站通用定律。执行功能页新增或优化时，用以下规则校准：

- 每次只改一个主要元素：title、meta、H1、事实层、正文内容、schema、内链块、布局位置或图片，不要一次改完整页面后声称知道哪个元素有效。
- 为重要改动写清假设：改了什么、影响哪类页面、预期影响 SEO 指标、预期影响 GEO/AI 引用、可能伤害什么转化或体验。
- SEO 与 GEO 可能冲突：传统 CTR 变好不代表 LLM 引用变好；meta、答案块、事实表和结构化数据要同时考虑搜索结果展示与模型抽取。
- 内容测试出现负面结果时，不直接判定内容无价值；先检查是否把工具入口、证明、价格、限制或用户更需要的模块挤到了更差位置。
- 大块 SEO 文案、FAQ、链接墙或规格表不能压过工具可用性；如果增加内容影响首屏任务、速度、CLS 或转化，优先缩短、重排或测试移除。
- AI 生成页面内容必须有人审查产品事实、法律承诺、品牌表述、竞品误写、图片 alt 和本地市场语境；不要大规模瞬时上线未经验证的 AI 文案。
- 价格、积分、库存、模型版本、限制等会变化的事实，能服务端输出就服务端输出；若暂时只能客户端输出，必须避免 SERP、页面内容和真实状态互相矛盾。

## 文案规则

- `seo.title`：优先 50-60 字符；关键词尽量靠前，但可为了可读性不放第一个词。
- `seo.description`：优先 145-160 字符；每页唯一，自然包含关键词，并说明真实价值、适用范围或关键限制。
- H1 与 title 同向，但不能机械复制；工具页允许首屏工具面板先于正文 H1，只要主标题和核心说明可抓取。
- title、H1、meta 不夸张、不震惊体，不为了 CTR 承诺页面没有交付的结果。
- meta description 不直接决定排名，但可能影响搜索展示、CTR 和 AI/LLM 摘取；不要为了“Google 会改写”而留空或写成模板废话。
- CTA 使用具体动作词。
- 没有证据时，不写 `free`、`best`、`instant`、`no signup`、速度、精度、质量或模型能力承诺；有真实工具入口、限制说明或产品证明时才可写。
- 模板没有字段时，写进最接近的现有字段；不要随意新增 JSON key。

## 关键词覆盖与密度校准

**先量竞品，再定靶子。禁止使用任何来自记忆或客户口头传闻的密度数字。**

### 「2% 密度」是有歧义的，读错就是堆词

密度有两种算法，对多词短语相差数倍：

- `hits%` = 出现次数 ÷ 正文总词数 —— **多数密度插件用这个**
- `span%` = 出现次数 × 短语词数 ÷ 正文总词数 —— 文本占比

用户说「核心词密度做到 2%」时，必须先判定口径。按 `hits%` 对一个 3 词短语追 2%，
2500 词的页面要塞 50 次，这是教科书级关键词堆砌，在 AdSense 审核或 spam policy 下是负资产。

### 流程：抓 3-5 个排名页，用同一段代码算

同时算三个数：正文词数、完整长尾词命中次数、单 token 命中次数。合理区间由竞品给出，不由直觉给出。

2026-08 实测样本（AI 水印去除类词，竞品均排在委托方之前）：

| 竞品 | 正文词数 | 完整长尾词 hits% | 单 token |
|---|---|---|---|
| A（该词第一梯队） | 423 | 0.47% | 4.73% |
| B | 970 | 0.62% | 3.71% |
| C | 1030 | 0.10% | 0.10% |

**三个赢过委托方的页面，完整长尾词没有一个超过 0.62%。** 所以「2%」只可能指单 token。
采用的靶子：完整长尾词按次数卡下限（≥8 次），单 token 写到自然为止。

### 长页面的密度陷阱

深度内容页常有 2500-4000 词，是短页竞品的 3-9 倍。**同样自然的重复次数，密度被分母摊薄到 1/3。**
不要为追平短页竞品的密度而灌品牌名，也不要为提密度而砍掉真实信息 —— 两者都亏。
密度短于目标时，如实报告并说明推高需要多少次额外提及，由用户决定是否接受堆词风险。

### 最该查的不是密度，是「有没有」

零命中是常见的静默失败。实测某 8 页站点，**4 个页面的目标长尾词在正文里出现 0 次**，成因：

- **H1 与 title 用词不一致** —— title 写 `PDF Slides`，H1 只写 `PDF`
- **修饰词插在短语中间把它劈断** —— `Gemini Visible Watermark Remover` ≠ `gemini watermark remover`
- **用了没有搜索量的同义词** —— autocomplete 里 `metadata remover` 有量，`metadata cleaner` 零

### ⚠️ 反灌水规则会把头部词挤出正文

当内容规范要求「每句话必须带具体数字、真实限制或诚实失败模式」时，写作者会把所有指代压成
`this tool` / `the engine` / `the page`，头部词随之从正文消失。**这两条规则天然冲突，必须显式对冲：**

- H2 写工具全名，不写 `How it works` / `At a glance` 这类通用标题
- 指代词换实名 —— **零新增字数的提密度手段，优先于任何新增句子**
- ⚠️ 批量替换前必须逐条看上下文：PDF / 幻灯片类工具里 `the page` 常指**文档页**而非网页，
  `the site` 指站点，隐私段落里的 `this site` 换成工具名就是胡话；文件头注释也不该改

## 政策门槛

任一门槛不满足，交付前必须修正：

- People-first：页面先帮助用户完成任务，再承接转化。
- Who/How/Why：能看出谁提供工具或内容、工具/内容如何产生或审阅、为什么这个页面对直接访问用户有用。
- 模块匹配意图：由关键词和工具类型决定页面长度、首屏重点与模块顺序。
- 不做假工具：没有假上传、假生成、假进度条或不可实现承诺。
- 不做薄页 clone：至少有三处关键词专属价值点。
- 批量或纯工具页可以短，但必须真实可用、限制清楚、入口明确、内链合理；短不等于薄，换皮才是薄。
- 不为 SEO 增肥：无用、过时、堆词或挤占工具入口的文本可以删、移或压缩；更多内容不是默认更好。
- 不抓取改写：SERP 证据只用于研究，不改写竞品文案。
- 不制造 doorway/cannibalization：相似页面必须有清晰意图区分，必要时合并。
- AI 复核：事实、法务、产品能力和品牌表达必须检查。
- 结构化数据诚实：schema 内容必须可见且有效。
- 导航完整：不劫持返回按钮、不污染 history、不强制跳转、不用阻断脚本。

### 全页兜底检查

最终输出或 diff 前再检查：

- 只有一个 H1。
- title、meta、H1 每页唯一，且准确描述页面内容。
- title、meta、slug、H1、首段、alt 自然覆盖关键词。
- **主关键词在正文中的命中次数已实测，不是目测**；H1 完整包含它，中间没有劈断短语的修饰词。
  0 次是静默失败，必查（见「关键词覆盖与密度校准」）。
- 密度对照的是**本次实测的竞品区间**，不是记忆里的百分比；短于目标时如实报告而非补词。
- slug 短、可读、能反映工具任务；不要依赖随机 ID 或无意义路径表达主题。
- H2/H3 层级清晰。
- 核心 H2 下有可独立引用的直接答案或任务说明。
- 内容在可抓取 HTML 中。
- Googlebot 可见内容与用户可见内容一致；关键文案、链接、图片说明不能只存在于不可抓取交互态。
- AI/LLM crawler 可能不执行 JavaScript；关键事实、价格/积分、限制、格式、模型、内链和答案块不能只依赖客户端渲染。
- 页面返回 HTTP 200，未被 robots/noindex/login wall 阻断。
- canonical、alternate、breadcrumb、schema 沿用现有模式。
- 内链是真实 `<a href>`，且指向相关页面。
- 外链只引用官方或权威来源。
- 赞助、付费、affiliate 或 UGC 链接使用正确 `rel`。
- 图片有描述性 alt 和稳定尺寸或比例。
- Core Web Vitals 基线：LCP < 2.5s、INP < 200ms、CLS < 0.1。
- AI search readiness：定义直接、答案简洁、步骤清晰、实体命名一致、事实可引用。
- GEO readiness：fan-out 查询有覆盖，事实层可抽取，meta/答案块/schema 不互相矛盾，并记录 SEO 与 GEO 可能分歧的判断。
- 主要模块均提供信息价值，不能只做关键词换皮。
- 不按固定字数填充内容；长度由工具任务、SERP 意图和信息增量决定。

## 输出

1. **模板匹配**：选择的 route/JSON 与原因。
2. **工具页类型**：类型判断、首屏重点、必备模块、可省模块。
3. **SEO Brief**：意图、变体、fan-out 查询、FAQ、独特角度、相关内链。
4. **实现说明**：文件、route、JSON 路径和接线改动。
5. **优化后的 JSON**：英文，结构与模板一致。
6. **模块 QA**：逐模块说明信息价值、政策门槛、可抓取性、链接、schema、薄页风险。
